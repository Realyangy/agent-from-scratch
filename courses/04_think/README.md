# 04 Reasoning & Problem Solving｜CONCEPT

## 学习目标
理解复杂语言问题的推理需求、纯 LLM 推理的局限，以及为何真实 Agent 往往需要工具和外部验证。

## 什么是定量推理？
本节使用家庭聚餐购买土豆的英文问题。模型需要识别人物与亲属关系、在世条件、是否带配偶、儿童人数、不吃碳水的例外、每人消费量和包装规格，最后计算需要购买多少整袋。

## 为什么困难？
多条件的计数题容易发生：
- 忽略例外情况；
- 同一位家庭成员重复计数；
- 误解亲属关系、婚姻与存活条件；
- 乘除换算、取整错误；
- 只输出一个看似合理但未经验证的数。

## System Prompt 的作用
原版指令要求模型专注逻辑与数量推理，并只给最终数字。这样能简化输出，但并不保证正确；输出没有过程也不便于核查。

## Prompt 推理的能力边界
LLM 擅长自然语言解释和模式识别，但复杂、精确计算更应交给确定性程序完成。可以要求结构化中间结果，再用 Python 验证单位和数值，而不只接受最终答案。

## 从纯 Prompt 到 Agent 的进化
~~~text
Prompt only → 结构化计划 → 计算器工具 → 反馈循环 → 可验证答案
~~~
第 07 节的 Function Calling 和第 09 节的 ReAct 就是重要进展。

## Chain of Thought 与验证
模型生成的文字分析并不自动等价于可靠的内部推理过程。可检查的变量、工具返回值和验证器对工程系统更重要。
